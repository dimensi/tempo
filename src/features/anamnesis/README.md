# Анамнез

Модуль персональной медицинской истории: импорт лабораторных PDF, каталог
показателей, история измерений с происхождением, очередь ручной проверки,
единый доступ тренера и PDF-отчёты.

## Границы модуля

- Сервер: `src/server/anamnesis` (сервис, репозиторий, конвейер импорта,
  воркер, отчёты) и `src/server/storage` (общее объектное хранилище).
- UI: `src/features/anamnesis`, маршруты `src/app/(dashboard)/anamnesis/*`.
- API: `src/app/api/anamnesis/*`, контракт `src/contracts/anamnesis.ts`,
  права `anamnesis:read` / `anamnesis:write` / `anamnesis:report`.

## Контракт

- Значения измерений — десятичные строки (не JS number).
- `verification` (доверие распознаванию) не зависит от
  `referenceAssessment` (отношение к референсу).
- Автоподтверждение требует: однозначный показатель, значение в источнике,
  корректный тип, известную единицу (или её отсутствие), дату и отсутствие
  противоречий. Вне референса сохраняется автоматически.
- Дедупликация: sha256 файла → повтор источника внутри PDF → точное
  совпадение измерения между документами (добавляется источник).

## Доступ тренера

Общий `trainer_access` и его флаг `anamnesis_access` разрешают тренеру все
текущие и будущие показатели, источники и оригиналы PDF вместе. Владелец
управляет одним переключателем на тренера в `/settings#trainers`.
По умолчанию медицинский доступ выключен. Отзыв любого из двух разрешений
блокирует медицинские чтения и отчёты; после асинхронного чтения файла или
подготовки отчёта сервер проверяет доступ повторно. Тренер не может менять
разрешение или медицинские данные; другой владелец и MCP не получают доступ.

Миграция 0025 сохраняет существующие разрешения: хотя бы один прежний грант
показателя или PDF включает единый доступ для той же пары владельца и тренера.
Без прежних грантов флаг остаётся выключенным. Удаляются только таблицы
выборочных разрешений; медицинские данные и документы сохраняются.

## Тесты

Существующие сценарии `tests/integration/authorization.test.ts` и
`tests/integration/migrations.test.ts` проверяют общий доступ, отзыв при чтении
PDF, изоляцию владельца и сохранение данных при миграции. Отдельные тестовые
сценарии и E2E для этого переключателя не добавлены.

## Ограничения

- Реальное распознавание сканов требует `OPENROUTER_API_KEY`.
- Отчёты не включают оригинальные документы — только измерения.
- Визуальная подсветка источника доступна только для страниц с текстовым
  слоем; для сканов приводится цитата и номер страницы.

## Единая страница и экспорт

`/anamnesis` содержит постоянно смонтированные секции `#markers`, `#documents`,
`#export` с TOC и историей якорей. Загрузка, распознавание и проверка строк находятся
рядом с документом. Медицинские гранты перенесены в `/settings#trainers`.
Прежние страницы списков удалены; детали показателей и оригиналы остаются.

Вход отчёта — `{ markerIds, dateKeys }`: `null` означает всю историю, массив
содержит дни `YYYY-MM-DD`, месяцы `YYYY-MM` и/или `undated`. Неизвестная дата
и месяц не заменяются выдуманным днём. `POST reports/dates` возвращает ключи
с количеством измерений для выбранных показателей. `POST reports/preview`
возвращает подготовленный HTML, число A4 и SHA-256 снимка. Создание PDF требует
тот же выбор и `snapshotKey`; изменение данных вызывает 409 и обновление превью.
Предпросмотр обновляется через 300 мс, предыдущий запрос отменяется. Поздний
ответ не заменяет актуальный. Превью изолировано sandbox iframe и CSP.

Превью и PDF используют один подготовленный HTML: группы идут подряд,
заголовки повторяются при фактическом переносе. Значения, даты, единицы и
референсы не пересчитываются. Файлы — неизменяемые снимки; `file?inline=1`
открывает сохранённый PDF с новой проверкой grants и `no-store`.
Миграции 0013/0014 сохраняют прежние периоды в `historical_period_json`,
новый точный выбор — в `date_keys_json`. Storage keys и файлы не меняются.
