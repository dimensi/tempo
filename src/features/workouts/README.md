# Workouts

`/workouts?date=YYYY-MM-DD` is the single daily workspace. Each local workout is one persisted record with one title, note and ordered exercise/set list. Multiple real workouts on the same date remain separate entries.

The lifecycle is `planned → in_progress → completed`, with `completed → in_progress` through Continue. Create always starts planned. Start preserves all entered values; Complete confirms the remaining sets as results. Resume preserves the result and unlocks editing. There are no plan/result tabs, original-plan comparison fields, per-set completion checks or entered-set progress counter.

Owners and granted trainers can create and edit planned and in-progress workouts, record results, start, complete, resume and delete workouts, and manage personal workout videos. Completed values are readonly until Resume. These rules are checked on the server, including revisions and idempotent command retries.

Each exercise can retain optional fatigue (integer 1–10) and failure (`full`, `partial`, `none`); null/absent means not specified. Owners and granted trainers can edit these during execution and after completion without Resume. The dedicated feedback mutation checks revisions and stable retry IDs, updates only the named occurrence, and never triggers TransformMate publication. Both roles save feedback through the same durable queue and retain unsent input in drafts; explicit feedback conflict resolution reapplies only assessments on the latest server values. Copying to another date clears assessments. Provider/native workouts remain readonly. Publication schemas explicitly omit local assessment fields from transport and fingerprints.

While the workout screen is open online, an SSE connection receives initial and changed workout revision signals. The server checks the owner-scoped revision list once per second; the client reloads saved workout and sync projections without triggering a provider refresh. Creation, edits, transitions and removal appear automatically for both owner and trainer. Clean editors adopt the latest values and revision together. Dirty or pending local input stays intact; simultaneous edits still use the existing explicit revision conflict flow. The stream checks access once when opened and closes on navigation, disconnection or logout.

Both editable states auto-save after a 1200ms pause. Background saves do not disable inputs, remount the editor, replace newer input or activate field validation. Valid edits save independently of incomplete rows: new incomplete sets stay in the bounded account-scoped draft, while an edited existing set retains its last valid values in the server projection. The draft keeps those values with the row across deletion/reordering and navigation; they are never part of the API payload. Older incomplete drafts without that row metadata retain the saved exercise's sets until the incomplete input is resolved. The status identifies unfinished input instead of claiming everything is saved. Only explicit Save, Start or Complete activates inline validation; editing clears that validation. Creating an empty plan is allowed; Start and Complete require exercises with valid sets. Queued workout writes from both roles preserve their order, partition, revision and stable operation identities. Ambiguously delivered pre-migration operations remain reviewable rather than being silently resent with changed fingerprints.

Exercise discovery keeps the existing full-screen phone picker and desktop dialog, manual entry, muscle filters, multi-selection and inline technique playback. Add set copies the current weight and repetitions from the last set of that exercise; without a previous set it starts empty. Keyboard activation focuses the new weight field. Copying to another day creates a planned workout with fresh workout/exercise identities. Removing saved exercise occurrences remains an explicit online action with existing personal-video cleanup and confirmation.

Technique, personal videos and route-composed comments remain available when completed. Provider/native workouts remain readonly and retain unsupported metrics. TransformMate publication snapshots are transport reconciliation data, not a second local workout model; execution edits never republish a plan. The download control remains hidden while its cache/video implementation is retained.

The migration preserves session and exercise identities, personal videos, comments, every historical result, parent text and empty actual occurrences. Old nested plan IDs are retained when unique and remapped when necessary; immutable identity metadata supports restoration of old drafts. Migration 0022 repairs legacy duplicate exercise IDs and provider occurrence keys within a workout, preserving the first identity, exercise order, values and media references. Only affected records receive a revision increment so stale drafts cannot silently overwrite the repaired identities. It also applies to databases that already ran 0021; the earlier migration remains unchanged. Original numeric plan snapshots are removed from local workout records. Existing read-cache bodies must validate against the new version-2 contract; cache replacement does not clear pending writes.

Verification tier: Full. Existing unit, integration and browser smoke scenarios cover migration/data integrity, lifecycle guards, real authorization, durable writes and editing continuity. No new test cases; actual executed checks and final SHA are recorded in the task report.
