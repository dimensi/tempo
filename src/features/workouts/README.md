# Workouts

`/workouts?date=YYYY-MM-DD` is the single workout workspace. It combines the selected plan and its latest local result; additional real sessions and provider records on a date remain available through a selector. The old create/detail/result routes were removed.

Plan title and description stay visible in plan mode. Status actions use visible text: Finish in the header or Cancel completion beside completed status. Empty device-write panels are omitted; offline, retry and review cases appear inline with their existing resolution actions.

Cancel completion changes only status against the latest durable queued or acknowledged session and its matching revision. It preserves unsaved form fields and their dirty state rather than submitting them as result edits. The existing smoke checks this with a cleared exercise draft and compares persisted exercises, note and plan snapshot before and after reopening.

The page owns the date ribbon; the application header owns the section title and actions. Exercise discovery remains available inside the add-exercise task. The standalone catalog at `/workouts/catalog` is a nested desktop navigation item and a mobile More item. Each catalog card links to `/workouts/catalog/[id]` and offers copy/share actions. Exercise pages use the current accessible owner context and existing authorized catalog reads; URLs contain no sender identity or permission token. Login preserves a validated internal exercise destination. Provider reads use the shared read store. Refreshing upstream is an explicit action; a requested update shows a short inline result, without a status modal or permanent blinking panel.

Creation and plan editing use a multi-select exercise picker with a manual option, visible body categories and muscle filters. It is a full-screen task on phones and a wide focused dialog on desktop. Cards expose technique playback inline without a details sidebar. One selected workout is edited while preserving all other workouts and the plan period. Copying creates fresh planned identities and no actual results. Plans still use the authorized existing publication service.

Execution uses the same exercise/set layout. Actual repetitions start empty; numeric results come only from entered sets. Visible «По плану» and Tabler trash controls fill from the plan or remove a set in one click. Both targets are at least 44px high, placed below numeric fields on phones and alongside them on desktop. The last remaining set cannot be removed; its disabled control has a tooltip and accessible explanation that the whole exercise can be removed through the exercise menu. There is no separate Clear action or interactive filled check button. Weight missingness stays null. Stored actual occurrences may contain no recorded sets, preserving identity and attached video references; they open with a blank input row without invented values or a database repair. Planned exercises still require a set. Autosave retains recorded occurrences, and status-only changes retain every occurrence, including those without sets. Valid results save after an 800ms pause in input without requiring blur, through the durable owner write queue with revision and account checks. Plan saving remains manual. Adding an occurrence to an offline result is allowed; removing an existing occurrence remains blocked to protect attached videos. Changes that remove recorded occurrences require explicit confirmation because attached personal videos are deleted too; they use the existing online session API and retain the draft on failure.

Plan and actual records remain separate persisted contracts. Historical snapshots never change with plan edits. Trainers may edit plans and read granted results; only the owner records results. Native/provider results remain read only and preserve unsupported metrics.

Names open a focused media dialog: technique first, personal performance videos on a second tab. The description remains visible below the player. Players mount on request and dispose on close. Visible cards may load video metadata for the first frame when no poster is available. Private-video ownership, upload resumption and server authorization remain mandatory. Comments are composed once at the route layer for the selected actual session; feature modules never import one another.

Drafts have stable actor/owner/resource/day identities and carry both acknowledged plan and session revisions; stale bases are shown as conflicts before any write. They are bounded to eight entries, 256000 characters and twelve hours using the existing draft storage. Session reset clears drafts. Failed saves preserve input. Device writes are not removed by read-cache reset.

An explicit “Скачать тренировку” action retains the loaded workout resources and each exercise detail through the common read cache, then saves all available technique MP4s in the existing account-scoped file store. It confirms resource persistence and records a bounded download receipt only after all available videos are stored. Partial attempts keep completed videos for retry; exercises without a source video are named separately. The button is blocked while the day editor has unsaved changes. Saved technique is preferred during playback even while online. Session reset aborts active downloads and the common logout purge clears receipts, reads and files. Existing file limits still apply (30 files / 300 MiB total, 256 MiB each); failures retain completed work. This prepares an already loaded day, not a separate offline router or cold-boot shell.
