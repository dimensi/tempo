# nutrition

Дневник отображает нормализованные записи и их вычисленные итоги. UI не пересчитывает питание и не заменяет неизвестные значения известной частью суммы. Сравнение со сводкой YAZIO раскрывается отдельно; расхождения и неполные итоги остаются видимыми.

Поверхность ограничена 960 px. КБЖУ имеют одинаковые цвета и текстовые подписи на уровне дня, приёма пищи и записи. На телефоне значения располагаются в две колонки, записи — отдельными строками внутри приёма пищи. Отсутствующие необязательные сведения о порции/массе скрыты, реальные нули сохранены. Компактная полоса «Соотношение БЖУ по массе» доступна только при трёх известных неотрицательных значениях и положительной сумме; это не прогресс до цели. Контракт не содержит цели, поэтому колец прогресса нет.

Пустые приёмы пищи скрыты по общему `hasNutritionMealContent`: запись (включая реальные нули), связанное фото или любое ненулевое значение в вычисленных, известных либо официальных итогах сохраняет блок. При полном отсутствии содержимого остаются авторитетные итоги дня и одно сообщение о пустом дневнике; незагруженный день по-прежнему обозначается отдельно. Математика итогов не меняется.

Фото сопоставляются точно по `date` и `daytime` безопасного DTO и показываются с `contain`. DTO связывает фото с приёмом пищи за день, а не с отдельной продуктовой записью: название блюда не используется для сопоставления. Ручное удаление по-прежнему требует подтверждения; фото YAZIO доступны только для просмотра. Загрузка в дневнике отсутствует.

`tests/e2e/diary-ui.spec.ts` использует только синтетические данные и проверяет desktop/mobile, частичные и нулевые итоги, сравнение, условную полосу БЖУ, группировку фото и подтверждение удаления. Изображения тестов не являются пользовательскими фотографиями.

«Обновить день» доступно только владельцу и вызывает `POST /api/nutrition/days/[date]/refresh` для выбранной даты. Сервер проверяет сессию, роль, публичный Origin и календарную дату в часовом поясе браузера; существующий durable lease блокирует параллельные загрузки владельца. Режим `day-refresh` не меняет начало истории, часовой пояс расписания или его включение. Клиент подавляет повторный запрос во время загрузки и игнорирует поздний ответ после перехода на другую дату; завершение обновляет только всё ещё выбранную страницу.

Только этот режим использует независимую обработку ошибок фото: успешно загруженная еда, включая пустой день, сохраняется, а недоступные фото отмечаются отдельным предупреждением. При ошибке списка фото сохраняются существующие фотографии. Ошибка еды или нормализации остаётся ошибкой еды. Политика загрузки диапазона и автоматического расписания не изменена. Тесты `diary-refresh.spec.ts`, scheduler/sync и реальные сессии в connection-тестах проверяют эти границы на синтетических данных.
