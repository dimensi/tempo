# Manual measurements

Public UI: `MeasurementsPanel`, `measurementMessages` from the feature entry.
`MeasurementsPanel` receives the authorized `WeightHistory` projection. Its existing weight chart uses separate local/YAZIO series under the documented single-owner kg confirmation, retaining every same-day observation and nullable imported values. Other metrics and local CRUD are unchanged.
Contract: `src/contracts/measurements.ts`; date-only ISO `measuredAt`, decimal strings (positive, at most three decimal places), metric-specific kg/cm, partial unique metric sets and nullable note.

HTTP: GET/POST `/api/measurements?ownerId=…`, PUT/DELETE `/api/measurements/:id?ownerId=…`. Writes require owner permission; reads require owner identity or explicit trainer grant. All persistence queries include ownerId. PUT replaces the full partial metric set.

Browser writes require an Origin matching the configured public `BETTER_AUTH_URL`, including behind a reverse proxy whose internal request URL differs. Missing or foreign origins are rejected; forwarded headers do not widen trust. The page checks the same write permission as the API. Trainers see read-only history and charts, without a measurement form or mutation buttons. Save failures preserve the draft and distinguish invalid inputs, expired sessions, access denial and temporary failures.

Server composition: `listMeasurements(headers, ownerId)`, `getMeasurement(headers, ownerId, id)`, `measurementExists(headers, ownerId, id)`. Every public data entry authorizes owner scope. Explicit changed supported metrics queue YAZIO synchronization; demo data is never persisted.

Integration requirement: coordinator exports `measurements` from `src/server/db/schema/measurements.ts` in the aggregate schema, then generates/applies the SQL migration serially. No migration is generated by this feature. Existing trainer grants have presence semantics; active/revoked grant lifecycle must be enforced by the shared authorization guard when that coordinated core change is integrated.

E2E CRUD requires this migration in the prepared E2E database; security scenarios use real Better Auth login. Charts require the shared Mantine charts stylesheet (`@mantine/charts/styles.css`) in the root stylesheet composition; the feature does not edit shared layout.

## YAZIO body measurements

Weight is kg for this owner. Waist, hips, chest, thigh and biceps (upper arm) are cm; neck remains local. Saves atomically queue only explicit changed supported fields. Existing history is not uploaded on migration, startup or reconnect. Local save succeeds independently of provider availability.

Provider UUID links prevent echo writes and duplicate weight chart series. Pull preserves local notes, neck and distinct same-day observations. Date edits retain the old provider record and create a new UUID at the new local date; no remote DELETE is exposed. Sending/uncertain intents require date-summary UUID readback before retry. Explicit owner retry reuses the same UUID snapshot and applies saved local values after fresh comparison; no server idempotency guarantee is claimed. Higher provider precision is retained raw and reported without rounding.

Measurement DTOs include per-metric sync status. POST /api/measurements/:id/retry remains owner-write and trusted-Origin protected. GET /api/measurements/sync?ownerId=... exposes authorized precision issues. Process-local coalescing retains new work; native fetch aborts/drains within30seconds. Logical connection fencing uses nutrition_schedule.epoch, not the OAuth-refresh token-envelope generation.
