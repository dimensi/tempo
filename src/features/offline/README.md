# Transparent owner offline application

OWNER pages automatically verify identity and save a validated device copy while open. There is no toggle, manual range or separate reader interface. The public static application shell uses the same application frame, content layout, diary view/date navigation and workout read presentation as ordinary routes. The connected Next adapters retain server authorization and Next navigation. Offline navigation keeps ordinary browser URLs, uses browser history and reads IndexedDB. Settings/analytics/reports/overview remain network-required sections; local manual measurement capture is provided by the OWNER write queue; unknown dates/details show the inline message “Нет сети, эти данные ещё не загружены”. No authentication, private SSR/RSC or API response is cached.

Diary observations, related health/measurement observations and photo bytes retain today plus the previous 14 calendar dates in the browser timezone. Every read/commit atomically prunes diary/photos. Saved workout dates, canonical readonly links and literal local/native/fact projections remain independently bounded: 300 known dates, 1000 planned workouts and 300 each of sessions/native/facts, all sharing a 4 MiB JSON quota. Visiting an older workout route captures that local persisted date after the normal page loads; successful ordinary workout reads also trigger capture. The copy does not promise unseen provider data, catalog details, comments, exercise descriptions or video. Native literal plan/fact metrics stay readonly. A rolling diary refresh replaces workout records for its dates and retains older captured dates; account/provider changes erase all collections.

Only strict canonical browser-visible workout href locators are added to the safe snapshot. Parent/session associations and stripped plan snapshots retain local comparison. Owner IDs, account scopes, provider exercise/protocol IDs, signed media URLs, expected/baseline provider payloads and tokens are omitted. Old snapshots missing required route fields fail strict parsing and physically clear their snapshot/photos before authenticated refill. There is no old-format renderer.

Connected identity verification precedes cached display; network verification failure conceals the copy, and 401/403/409 purges it. Disconnected viewing cannot observe server revocation and does not extend server authorization. Genuine server expiry observations are preserved without a browser TTL claim. Clock rollback, owner/connection partition, IDB CAS generation, durable device epoch, logout/account/role/provider changes and all-tab/BFCache concealment remain enforced. Auth/provider mutations hold a same-origin Web Lock across purge-before, request settlement and purge-finally so automatic activation cannot refill while the mutation is pending. Actual auth operations still execute when physical storage cleanup fails.

The worker serves only the explicit versioned public static bundle from CacheStorage. Document GET navigation uses the network first, falling back on network failure for ordinary supported routes (including nested workout read routes and network-required section placeholders). HTTP errors and API/RSC fetches are never replaced with a shell. OWNER local results and manual measurements use the durable queue described in `docs/architecture/offline-writes.md`; other offline editors/sync/photo actions retain their network requirements. Reconnect verifies current identity and reloads a genuine server route. The worker keeps /offline-sw.js with scope /, completes precaching before removing old static caches, and retains the previous worker on failed installation.

`tests/offline/production.config.ts` uses one already-built standalone artifact with isolated synthetic Better Auth users, .data/e2e.sqlite and localhost HTTPS 3160→3161. It covers automatic population, older workout capture, ordinary navigation/cold reload, unknown dates, disabled writes, denial/trainer/account/purge barriers, storage failures, retention and successful/failed worker updates. Offline cases are excluded from the generic development browser suite and run once against the production artifact in CI.

Automatic cache enable/read/download/commit/publication holds an actual same-origin shared Web Lock with `ifAvailable:true`; it skips rather than queues when an exclusive auth/provider request is pending or held. User mutation intent synchronously conceals private containers and writes a distinct durable intent marker before the exclusive lock wait, aborting current reads. Storage enable/read/commit and photo revelation also reject that intent marker. Each mutation removes its own marker only after final purge; interrupted cleanup fails closed rather than reopening a copy. Unsupported Web Locks make automatic caching explicitly unavailable; authentication still executes if cache/storage/lock setup fails, without replaying an already-started request.

Detail capture uses the authorized resource's actual date, independent of optional navigation return-date queries. Linked cached native/fact results remain visible next to a local plan exactly once, without translating literal provider metrics. Evicting any workout record invalidates complete-day coverage for that date, while truly loaded empty dates remain known. Photo mappings are usable only for their current validated bundle/IDs, and enlarged offline photo portals carry the synchronous private-content conceal marker.
