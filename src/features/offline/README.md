# Кеш чтения и локальные записи

Принятая модель — [ADR 002](../../../docs/decisions/002-resilient-client-reads.md) и [клиентский кеш](../../../docs/architecture/client-read-cache.md). Кешируются загруженные ресурсы; cold offline boot и отдельный shell не требуются. Next.js остаётся единственным маршрутизатором.

Прежние controller, публичный boot entry и device fences удалены. По прежнему адресу SW публикуется retirement worker, который удаляет только собственные shell-кеши и снимает регистрацию.

Схемы и обработка отказа доступа принадлежат общему слою данных, а не feature UI. Старые данные отключённого тренера допустимы до обнаружения серверного отказа; после `AUTH_REQUIRED`/`ACCESS_REVOKED` общий клиентский обработчик завершает сессию и очищает кеш. Классификацию выполняет общий серверный API-обработчик; клиент использует общий transport.

[Очередь локальных записей](../../../docs/architecture/offline-writes.md) сохраняет существующую идемпотентность, owner partition, атомарность и конфликты. Её готовность не должна зависеть от snapshot или SW. Сохранённый файл не означает наличие автономного приложения для его открытия.
