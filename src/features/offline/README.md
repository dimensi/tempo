# Offline reading

Основные маршруты используют обычную оболочку и общие компоненты чтения. Версия DTO — 2; OWNER и разрешённый TRAINER изолированы по reader/role/owner/session/connection. Существующие серверные permissions и grants остаются обязательными. Настройки владельца тренеру не кешируются.

Контроллер и публичный протокол SW находятся в `src/lib/offline-controller.ts` и `src/lib/offline-shell.ts`, чтобы общая кнопка сохранения файла не зависела от feature-модуля. IndexedDB, durable gate, CAS fence, Web Locks и purge — в `src/lib/offline-device.ts`. Все приватные коллекции, включая явные PDF/video Blob, очищаются вместе.

Подробности дневника/замеров/тренировок/комментариев и фото — скользящие 15 дней. Годовые компактные наблюдения для аналитики, небольшой каталог и явно выбранные файлы имеют отдельные ограничения. Нет хранения signed URLs вместо байтов или массового скачивания PDF/видео. Отдельная очередь результатов тренировок и ручных замеров описана в [offline writes](../../../docs/architecture/offline-writes.md).

Успешные обычные чтения обновляют локальную проекцию. Результаты запросов дополняют `navigator.onLine`; отзыв доступа проверяется при соединении. Статическая версия устанавливается отдельно и ожидает закрытия прежних окон, без немедленного захвата клиентов.

Матрица разделов, лимиты, модель доступа, ограничения проверки и ручной чек-лист: [offline-read](../../../docs/architecture/offline-read.md).
