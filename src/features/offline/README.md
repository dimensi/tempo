# Owner offline reads

Default off. An OWNER explicitly enables “Доступно офлайн” under Settings → Offline-чтение. Open-app best-effort refresh saves today plus the previous14 local calendar dates; no manual range controls. Only validated offline snapshot DTOs and downloaded local photo blobs enter IndexedDB. Auth responses, cookies, credentials, raw HTTP responses, upstream URLs/videos, SSR/RSC, settings, PDF and mutations never enter it.

`OfflineController` verifies current OWNER identity before showing cached content on connected entry, focus, visibility, pageshow and reconnect. A network verification failure hides content and preserves the cache; it never bypasses a denied identity check. Disconnected entry uses prior explicit consent with truthful disclosure that server revocation cannot be observed offline. Downloaded local copies use rolling15 calendar retention independently of genuine server expiry observations. Persisted lastSeenAt rejects clock rollback. Every read/commit atomically prunes records and photo Blobs outside the local window. Online identity denial still blocks and purges; no server authorization is extended.

`OfflineStorage` atomically replaces a snapshot and its photo blobs. Its owner/connection/schema partition, IDB generation and independent localStorage epoch fence old writes. Disabling, logout, sign-in/account switch and provider changes durably block reads and synchronously conceal private containers before physical cleanup. BroadcastChannel, storage events and SW client messages clear all tab states. Pagehide conceals data before BFCache; pageshow revalidates before restoring it. Provider and auth changes purge before the request and again in finally after completion, clearing any sibling-tab cache saved while the request was pending. TransformMate connect/disconnect transport remains active through UI unmount or request supersession so final cleanup follows actual HTTP settlement; read requests remain abortable and current-request guards prevent stale UI updates. Auth actions still execute if physical cleanup fails; the offline reader stays blocked.

Diary meals use the shared content predicate: real entries, photo metadata or nonzero totals retain a meal; canonical zero/null meals are hidden. Day totals remain authoritative and an empty day has one clear state. Photo metadata retains a meal even when quota prevents saving its bytes. Photos are downloaded separately from metadata. Their budget is 50 MiB; failed/oversized images are marked missing, never represented by fabricated pictures or a completion claim. Displayed values preserve zero/null, and imported YAZIO weights use the account-specific OWNER-confirmed kg policy without conversion; raw persisted NULL SDK units remain unchanged. Workouts include local plans, sessions, already persisted TransformMate facts and native training history of the current confirmed account binding, including disconnected cached history. Native lifecycle, ordered plan/fact groups and literal metric values/units remain readonly; remote IDs/account scope/video URLs are omitted. Required nativeTrainings rejects and physically clears old snapshots/photos while preserving device opt-in; authenticated refill is required. No upstream request is made.

The generated service worker caches an exact versioned static-shell asset allowlist only. It passes API requests through and observes denial status without caching bodies. Navigation failure may return the public static shell for read routes; successful online responses and API/SSR/RSC content are never cached. `scripts/build-offline.mjs` uses existing esbuild/React/Mantine and shared theme; outputs are ignored and copied by the existing standalone packaging step. No new dependencies, credentials, schema or grants.
