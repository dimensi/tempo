# Owner offline reads

Default off. An OWNER explicitly saves a date period of at most 30 days under Settings → Offline-чтение. Only validated offline snapshot DTOs and downloaded local photo blobs enter IndexedDB. Auth responses, cookies, credentials, raw HTTP responses, upstream URLs/videos, SSR/RSC, settings, PDF and mutations never enter it.

`OfflineController` verifies current OWNER identity before showing cached content on connected entry, focus, visibility, pageshow and reconnect. A network verification failure hides content and preserves the cache; it never bypasses a denied identity check. Disconnected entry uses the prior explicit consent with TTL disclosure. Expiry is the minimum of server bounds, current session expiry and 24 hours from the snapshot's server time. Persisted lastSeenAt rejects clock rollback; reads do not renew expiry. A fresh identity with shorter expiry durably tightens the stored bundle through the same CAS fence before display.

`OfflineStorage` atomically replaces a snapshot and its photo blobs. Its owner/connection/schema partition, IDB generation and independent localStorage epoch fence old writes. Disabling, logout, sign-in/account switch and provider changes durably block reads and synchronously conceal private containers before physical cleanup. BroadcastChannel, storage events and SW client messages clear all tab states. Pagehide conceals data before BFCache; pageshow revalidates before restoring it. Provider and auth changes purge before the request and again in finally after completion, clearing any sibling-tab cache saved while the request was pending. TransformMate connect/disconnect transport remains active through UI unmount or request supersession so final cleanup follows actual HTTP settlement; read requests remain abortable and current-request guards prevent stale UI updates. Auth actions still execute if physical cleanup fails; the offline reader stays blocked.

Diary meals use the shared content predicate: real entries, photo metadata or nonzero totals retain a meal; canonical zero/null meals are hidden. Day totals remain authoritative and an empty day has one clear state. Photo metadata retains a meal even when quota prevents saving its bytes. Photos are downloaded separately from metadata. Their budget is 50 MiB; failed/oversized images are marked missing, never represented by fabricated pictures or a completion claim. Displayed values preserve zero/null, and imported YAZIO weights remain explicitly unknown-unit values outside kilogram charts. Workouts include local plans, sessions and already persisted TransformMate facts, with no upstream request.

The generated service worker caches an exact versioned static-shell asset allowlist only. It passes API requests through and observes denial status without caching bodies. Navigation failure may return the public static shell for read routes; successful online responses and API/SSR/RSC content are never cached. `scripts/build-offline.mjs` uses existing esbuild/React/Mantine and shared theme; outputs are ignored and copied by the existing standalone packaging step. No new dependencies, credentials, schema or grants.
