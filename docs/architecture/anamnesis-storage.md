# Объектное хранилище и анамнесис

Медицинские PDF и сгенерированные отчёты хранятся в S3-совместимом объектном
хранилище. База SQLite остаётся локальной на сервере приложения — на сетевой
том выносится только объектные данные.

## Текущее развёртывание (SeaweedFS на NAS)

- NAS: `tnas.local` (`192.168.1.90`), сервис SeaweedFS, бакет `apps`.
- Endpoint: `http://192.168.1.90:8333`, регион `us-east-1`, path-style.
- Ключ приложения ограничен бакетом `apps` (чтение, запись, удаление,
  листинг, тегирование); находится в `s3-apps.env` на NAS.
- Ключи приложения кладутся в переменные `S3_ACCESS_KEY_ID` /
  `S3_SECRET_ACCESS_KEY` приватной конфигурации развёртывания.

Ключи объектов анамнеза живут в пространстве имён `anamnesis/…` внутри бакета:
`anamnesis/<ownerId>/<sha256>.pdf` для документов (повторная загрузка тех же
байтов не создаёт новый объект) и `anamnesis/reports/<id>.pdf` для отчётов.
Скачивание всегда идёт через авторизованный маршрут API — публичных и
долгоживущих ссылок нет.

### Переменные окружения

| Переменная                                  | Назначение                                                                    |
| ------------------------------------------- | ----------------------------------------------------------------------------- |
| `S3_ENDPOINT`                               | URL S3 API. Пусто — локальный режим в `UPLOADS_DIR/object-storage`            |
| `S3_REGION`                                 | Регион (по умолчанию `us-east-1`)                                             |
| `S3_BUCKET`                                 | Бакет (по умолчанию `apps`)                                                   |
| `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` | Ключ приложения                                                               |
| `ANAMNESIS_LLM_BASE_URL`                    | OpenAI-совместимый API распознавания (OpenRouter)                             |
| `OPENROUTER_API_KEY`                        | Ключ провайдера; без ключа импорт сканов невозможен                           |
| `ANAMNESIS_LLM_MODEL`                       | Модель с поддержкой изображений (по умолчанию `google/gemini-2.5-flash-lite`) |
| `ANAMNESIS_LLM_TIMEOUT_MS`                  | Таймаут запроса к провайдеру, мс (по умолчанию `120000`)                      |
| `ENABLE_ANAMNESIS_WORKER`                   | Периодический проход очереди импорта в продакшене                             |

### Рекомендации по изоляции

1. Выделите отдельный бакет (например `tempo-medical`) и отдельный ключ с
   правами только на него через админ-панель SeaweedFS (SSH-туннель, см.
   notes по NAS). Медицинские данные получат собственное пространство.
2. Оставьте эндпоинт доступным только из локальной сети/VPN; публичный
   домен и проброс портов не настраиваются.
3. Отдельная резервная копия каталога данных SeaweedFS не настроена —
   выполните согласованный бэкап (остановка контейнера на время копирования
   либо штатная схема SeaweedFS). RAID1 не заменяет резервную копию.

## Разработка и тесты

Без `S3_ENDPOINT` используется локальная реализация в
`UPLOADS_DIR/object-storage` — тот же интерфейс `ObjectStorage`
(`src/server/storage`), что и S3. E2E работает только с ней.

Для распознавания в тестах предназначен детерминированный провайдер,
включаемый переменной `ANAMNESIS_EXTRACTION_FIXTURE_SHA256`: он отвечает
только на файл с точным совпадением хеша (контрольный «Синтетическая лаборатория») и не
затрагивает остальные загрузки. В продакшене переменную не задают.

## Чек-лист проверки хранилища

- [ ] SeaweedFS поднимается после перезагрузки NAS.
- [ ] S3 API доступен с сервера приложения (`curl http://192.168.1.90:8333`).
- [ ] Загрузка и скачивание PDF через раздел «Анамнез» работают.
- [ ] После рестарта данные сохраняются.
- [ ] Недоступность NAS обрабатывается: загрузка возвращает ошибку без
      потери уже сохранённых документов.
- [ ] Резервное копирование настроено и восстановление проверено.

## Операционный запуск (compose)

Шаблон `compose.yaml` в репозитории прокидывает `S3_*`, `ANAMNESIS_LLM_*` и
`ENABLE_ANAMNESIS_WORKER` из окружения Compose-проекта; серверный
`/opt/compose/yazio-dashboard` оператор обновляет отдельно — CD не трогает
серверный compose из git. Defaults ничего не включают: `S3_ENDPOINT` и оба
ключа пустые (fs-режим в `UPLOADS_DIR`), `ENABLE_ANAMNESIS_WORKER=false`,
LLM-ключ пустой — внешняя обработка не выполняется. Тестовая переменная
`ANAMNESIS_EXTRACTION_FIXTURE_SHA256` в compose-шаблон не входит и в
production не прокидывается.

### Таймер воркера

`ENABLE_ANAMNESIS_WORKER=false` отключает **только периодический таймер**
очереди импорта. Обработка запускается напрямую и без таймера: при загрузке
документа, при переобработке и при просмотре очереди импортов (`kick`). Тем
самым значение по умолчанию не блокирует импорт — оно лишь исключает
фоновый проход по аренде просроченных заданий.

### Передача данных внешнему провайдеру

Добавление `OPENROUTER_API_KEY` может передавать внешнему провайдеру
**текст и изображения страниц** лабораторных документов (vision-модель).
Включение ключа — только после отдельного согласования владельца; без ключа
внешняя передача не выполняется (сканы не распознаются автоматически).

### Переход fs → S3 и откат

Переход с локального fs-режима на S3 — скоординированная операция, не
конфигурационный переключатель:

1. **Инвентаризация**: снять перечень существующих объектов и заданий
   (ключи, счётчики) без выгрузки медицинского содержимого.
2. **Перенос**: скопировать объекты с сохранением ключей
   (`anamnesis/<ownerId>/<sha256>.pdf`, `anamnesis/reports/<id>.pdf`), затем
   сверить счётчики и sha256 каждого объекта с инвентаризацией.
3. **Бэкап NAS**: резервная копия SeaweedFS настраивается отдельно от
   volumes CD и не заменяется ими.
4. **Откат**: после того как в S3 появились **новые** записи (новые
   документы/отчёты, записанные уже в S3-режиме), простой возврат env к
   fs-режиму недопустим — часть данных останется только в S3. Откат требует
   согласованного обратного переноса с той же сверкой counts/hash.

Сам этот патч не выполняет никаких миграций и не активирует S3/LLM: он
только прокидывает переменные и документирует процедуру.

### Ограниченное распознавание страниц

OpenRouter получает страницы по одной, со структурированной JSON-схемой и лимитом
16384 выходных токенов на страницу. Ограничения длины/числа элементов проверяются
локально: в схему провайдера передаются структура полей и перечисления, поскольку
полная схема валидации превышает сложность constrained decoder. Ответ с
`finish_reason=length` не сохраняется и не запускает повтор той же страницы.
Все страницы должны успешно пройти извлечение до сохранения результатов документа.
Во время длительной обработки воркер продлевает аренду задания. HTTP 200 сам по
себе не означает успех: проверяются тело ответа, код завершения и исходная схема.
