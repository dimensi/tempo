# Общее объектное хранилище

`src/server/storage` — единая точка записи бинарных объектов приложения
(сейчас анамнесис, в будущем загрузки видео/картинок). База SQLite остаётся
локальной; на сетевое хранилище уходят только объекты.

## Интерфейс

```ts
interface ObjectStorage {
  put(key: string, bytes: Uint8Array, contentType?: string): Promise<void>;
  get(key: string): Promise<Uint8Array>;
  remove(key: string): Promise<void>;
}
```

- `getObjectStorage()` — процессный синглтон, выбор реализации по env.
- `fsObjectStorage` — локальный режим (`UPLOADS_DIR/object-storage`),
  разработка и E2E без NAS.
- `s3ObjectStorage` — S3-совместимый режим (SeaweedFS, path-style).
- Выбор: заполненный `S3_ENDPOINT` (+ оба ключа) включает S3; иначе fs.
  `S3_ENDPOINT` без учётных данных — ошибка запуска, молчаливого фолбэка нет.

## Контракт

- **put идемпотентен и перезаписывает** (семантика S3 `PutObject`): обе
  реализации записывают объект заново. Content-addressed ключи анамнеза
  делают повторную запись того же содержимого безвредной.
- **get ограничен 100 МиБ** в обеих реализациях — защита от расползания
  памяти.
- **remove идемпотентен**: удаление отсутствующего ключа не ошибка.

## Ключи и раскладка

Ключ — путь из сегментов `feature/…/name.ext`: строчные буквы, цифры,
дефисы и точки (точки — для расширений). Валидация
(`validateObjectKey`, `src/server/storage/keys.ts`) выполняется на каждом
put/get/remove в обеих реализациях — containment обязателен независимо от
вызывающего. Абсолютные пути, `..`, пустые сегменты, обратные слэши и
небезопасный хвост после валидного префикса отклоняются.

| Назначение        | Ключ                               | Особенность              |
| ----------------- | ---------------------------------- | ------------------------ |
| Документ анамнеза | `anamnesis/<ownerId>/<sha256>.pdf` | дедуп по содержимому     |
| Отчёт анамнеза    | `anamnesis/reports/<id>.pdf`       | генерация перезаписывает |
| Будущие загрузки  | `media/<ownerId>/<sha256>.<ext>`   | тот же интерфейс         |

Скачивание всегда через авторизованные маршруты API; публичных ссылок нет.

## Переменные окружения

| Переменная                                  | Назначение                             |
| ------------------------------------------- | -------------------------------------- |
| `S3_ENDPOINT`                               | URL S3 API; пусто — локальный fs-режим |
| `S3_REGION`                                 | регион, по умолчанию `us-east-1`       |
| `S3_BUCKET`                                 | бакет, по умолчанию `apps`             |
| `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` | ключ приложения, только свой бакет     |

Текущее развёртывание и чек-лист проверки — в
[anamnesis-storage.md](anamnesis-storage.md).

## Ограничение для будущих видео

Базовый интерфейс переиспользуется как есть, но рассчитан на малые объекты:
`Uint8Array` целиком в памяти, буферизованная запись и лимит `get` 100 МиБ.
Для больших видео нужен отдельный слой поверх того же модуля — streaming
(ReadableStream) и/или multipart upload, свои лимиты и прогресс; в текущий
интерфейс он не добавлялся. Новые потребители картинок ограничение не
затрагивает.
