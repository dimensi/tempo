# Retained offline navigation repair

Scope: pause hidden live screens, read saved meal photo bytes in the retained diary, disable offline menu prefetch and handle SW transport rejection. No SQL, queue, permissions, secrets, dependencies or CI changes.

A retained diary stayed active behind the saved route. Its date-normalization effect observed the shallow URL change to `/` and called `router.replace` back to `/diary`. The existing hidden div kept route effects and chart observers alive. A React Activity now pauses effects only for saved-route navigation while retaining DOM/component state. Access-denial concealment retains its existing behavior so pending denial handlers can finish clearing private models. Menu links disable prefetch while offline. The live diary resolves offline photos from the authorized controller's stored blobs, matching safe date/meal/source/observedAt metadata; ambiguous or missing bytes remain explicitly absent. SW fetch rejection resolves to `Response.error()` so the caller receives a transport failure without an unhandled worker promise.

A negative control replaced only the Activity with the old hidden div: the new browser regression failed on both profiles, with desktop reporting expected Overview / received Diary selection and mobile returning to the diary URL. Restoring the fix passes three complete loops over all eight primary menu entries, Back/Forward, local blob photos, one network status, no new live-photo requests, no page errors or zero-size chart warnings. All fixtures/writes use the isolated local E2E database. Physical devices and installed PWA are not verified by these Chromium profiles.
