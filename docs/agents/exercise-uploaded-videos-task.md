# Uploaded exercise videos

- Objective: show «Загруженные видео» beside an exercise after at least one fully uploaded recording exists (processing, ready or failed); open the personal-video tab directly, retain the shortcut after reload and hide it after the last recording is deleted. Clarify upload status and repair FilePond action icons and presentation. Keep uploads alive when switching media panels, closing the dialog, viewing another exercise or hiding the browser tab.
- Lifetime: visited media dialogs are retained by exercise key within the current workout. Closing a dialog hides it and unmounts playback only. Mantine uses `keepMountedMode="display-none"` so React Activity does not tear down upload effects after the exit transition. A stable portal host keeps the FilePond view laid out outside the dialog while hidden, inert and excluded from accessibility navigation; its scheduler can start the next file without reopening the dialog. Explicit visibility-based cancellation is removed; the browser may still suspend background work. Page teardown, account reset and manual pause still cancel safely.
- Scope: recordings of the exercise occurrence in the selected workout; cross-workout aggregation is deferred.
- Branch/worktree: `feat/exercise-uploaded-videos`, `/workspace/tempo-uploaded-videos`. No persistent preview or real user database; browser checks use only `.data/e2e.sqlite`.
- Owned paths: workout exercise rows/media, video list/queue and its stylesheet, feature-local messages and uploaded-video hook; existing workout browser smoke (holds a real upload part while switching panels, hiding the document and closing the dialog).
- Shared/core changes: none. Existing v1 workout/video contracts, storage, schema and permissions are unchanged.
- Access: owner and explicitly authorized trainer may read; existing owner-only upload/delete permission remains enforced on the server.
- Reads: one video-list request per workout; scoped request cancellation and session-generation checks; shortcut availability updates from the committed dialog list. No new persistent cache or routing layer.
- Fixtures: existing synthetic camera-video fixture and real test authentication; no production data.
- Verification tier: Full, because upload lifetime and hidden-dialog effects have an uncertain lifecycle blast radius. Run `pnpm verify:merge` on the clean final commit after rebasing onto current main; report its exact revision, case counts and durations in the PR. Existing FilePond desktop/mobile light/dark inspection remains applicable. No new test cases.
